# OCS 学习通多课程切换器

配合现有 OCS Desktop 与脚本猫运行，负责课程队列、进入第一章节和切换课程。无需修改或替换 OCS。

当前版本：0.2.2。

0.2.2 修复：勾选或取消课程时保留课程列表和面板的滚动位置；收起再展开也保留位置。已用 40 门模拟课程连续操作验证。

本次修复：

- 从封面链接旁的课程卡片标题识别名称，重新扫描可修正已有数字占位名，保留勾选和排序。
- 识别带 `NEW` 标记的“章节”按钮；处理嵌套章节列表和实际的 `toOld(...)` 首节入口。
- 修复导航尚未完成就检查旧页面身份引发的误暂停，等待队列状态保存成功后再离开页面。
- 默认 540px、18px 字体的大号悬浮窗；可拖动标题栏、收起，保存位置；支持三档大小。
- 课程列表单独滚动，避免课程过多时操作按钮被挤到底部。

默认流程：打开所选课程 → 点击第一个可点击章节 → 交给 OCS → 看到 OCS“全部任务点已完成！”提示 → 下一门。不会读取章节完成数量，不会处理答题、修改播放或提交学习记录。

## 安装与使用

点击 [安装最新版脚本](https://raw.githubusercontent.com/Cestlet/ocs-course-switcher/main/ocs-course-switcher.user.js)，由脚本猫接管安装。也可以下载文件后按下列方式导入。

1. 在 OCS 使用的浏览器里打开脚本猫的脚本管理页面。
2. 将 `ocs-course-switcher.user.js` 拖入脚本管理页面安装；若拖入不可用，新建脚本，将文件全部内容粘贴进去并保存。
3. 刷新学习通页面，右下角出现“OCS 多课程切换器”。
4. 在课程列表页点“扫描本页课程”，勾选需要的课程并调整顺序。
5. 如果列表页不能扫描，逐门打开课程，点“添加当前课程”。也可以通过“粘贴课程链接”输入每行 `课程名称 | 完整链接`。
6. 在用于运行队列的那个标签页点“开始队列”。每次自动打开课程后，脚本尝试进入第一章节，后续章节由 OCS 负责。

默认“收到 OCS‘全部任务点已完成’后切换”。定时切换是可选备用方式，定时到达不代表课程完成。

## 与 OCS 配合

- 关闭 OCS 的“完成全部后重新学习”，否则 OCS 可能回到第一章继续播放，而不产生完成提示。
- OCS 自身的章节跳转模式继续使用你的现有设置。OCS 开启“自动前往首个任务点”时，可能在进入第一章后自行跳到未完成章节。
- 只有完整的“全部任务点已完成！”提示才触发自动切课。“已到最后一章”“仍有任务点未完成”均不会触发。
- 本工具直接信任 OCS 的提示，不再次检查平台后台进度。因此它不能修正 OCS 本身对完成状态的误判。
- 运行时保持该标签页打开。同一队列只由点击开始的标签页执行；其他标签页只显示队列状态。
- “暂停”只暂停切换器。若要停止当前视频，请在 OCS 或播放器中暂停。
- 遇到登录失效或未找到章节入口会暂停并显示原因，课程队列保留。
- 如果未识别出章节入口，手动进入当前课程的第一个章节，再点“已进入章节”，即可继续等待完成提示。
- 如果首章被锁定，可能进入首个可点击章节；不绕过章节锁或验证。
- 新开标签页或重启浏览器后，可点“继续当前门”重新指定运行标签页。该操作会重新打开当前课程。

## 适配范围与当前验证

支持 `*.chaoxing.com`，已适配课程首页 `/mooc2-ans/mycourse/stu`、课程章节入口 `/mycourse/studentstudy` 以及常见 `getTeacherAjax` 章节按钮。学校自有域名和不同课程模板尚需单独适配。

“扫描本页课程”读取现有链接和同源 iframe 中的完整链接；无法从纯 JavaScript 参数式课程卡片自动构造缺失链接。此时使用“添加当前课程”即可。未接入课程列表接口，不需要填写账号密码。

队列和运行日志保存在脚本猫的本地脚本存储中；完整课程链接可能包含课程访问参数，不要公开分享自己的队列数据。脚本不请求第三方服务。

`verify.cjs` 用独立 Chromium 和离线模拟页面验证主要流程，运行后生成 `verification.json`。`verify-scroll.cjs` 用 40 门模拟课程验证滚动位置保持。

已在实际 OCS 浏览器验证课程名称扫描、从课程首页进入首节视频页，以及 0.2.2 脚本安装生效。自动完成提示后的跨课程切换通过离线模拟验证，尚未等待实际整门课程播放结束验收。

## 文件

- `ocs-course-switcher.user.js`：可直接导入脚本猫的完整脚本。
- `verify.cjs`：离线验证程序，使用本机现有 `playwright-core` 与 Chrome，无需安装 npm 依赖。
- `verify-scroll.cjs`：长课程列表的滚动位置回归验证。
- `verification.json`、`verification.png`、`scroll-verification.json`：本地运行验证后生成，不随源码发布。

重跑验证（PowerShell，路径按本机安装位置修改）：

```powershell
$env:OCS_PLAYWRIGHT_DIR = "$env:LOCALAPPDATA\Programs\OCS Desktop\resources\app\node_modules\playwright-core"
$env:OCS_CHROME_PATH = "$env:LOCALAPPDATA\Programs\OCS Desktop\resources\bin\chrome\chrome\chrome.exe"
node .\verify.cjs
node .\verify-scroll.cjs
```
